Install and first sign-in

  1. Use the prepared release supplied by R3. Right-click its ZIP and choose Extract All. Open the extracted folder; do not run from ZIP preview.
  2. Double-click Install-IZ-Clinical-Notes-Analyzer.cmd and wait for success. Then use the installed shortcut or Launch-IZ-Clinical-Notes-Analyzer.cmd.
  3. Sign in using your assigned app account. If given a temporary password, choose your own when prompted. Use at least 12 characters with a letter and number; a unique longer passphrase is easier to protect.
  4. When asked to set up recovery, enter your password, save the one-time recovery code privately and acknowledge that you saved it. Complete this before entering the workspace. Do not put the code in a screenshot or ordinary email/chat.
  5. Open Status Dashboard. Check the footer version and any readiness or unresolved-policy warnings.

Normal prepared-release use does not require administrator access, Python, Git, Node.js, Docker or PostgreSQL. If Windows blocks a supplied file, contact R3; do not turn off Windows protection.

An upgrade preserves existing passwords and local records. The starter password cannot unlock an already initialized account. Never use complete uninstall to perform an upgrade.

Daily review: find the exact record

  1. Start and sign in. Open Dashboard, then Patient Roster. Clear filters if records seem missing; check the Source selector.
  2. Search using the MRN or other authorized reference. Open the MRN for Patient Record Detail. A patient may exist without any treatment plan.
  3. Select a saved plan, or open one from Treatment Plans Roster. Confirm source, MRN, plan ID and saved version ID. The same identifier can occur in another source/facility; a name alone is not proof of identity.
  4. In Treatment Plan Detail, compare signatures, admission date, source Next Review Due, calculated due date, LOC history and warnings. Use the saved-version selector to inspect history. A new import does not silently change an existing selection.
  5. Search the 42-step checklist. Open the relevant criterion and inspect the evidence/source path. Resolve missing or conflicting information against the original source.
  6. Use the approval, return, correction, comment or override actions your role permits. Give a reason when required. An override records your decision; it does not rewrite the source or confirm an unresolved policy.

CSV exports include matching filtered rows even below the screen, omit names/narrative, and still contain sensitive identifiers and dates. Share only through an approved R3 channel.

Dates and statuses

The initial signature is checked on admission Day 1. A signed master plan is due within 30 calendar days after admission. Recurring PHP reviews use 30 calendar days; IOP/OP use 60 calendar days. The recurring clock starts from the latest valid signed review, or admission when no valid review exists. The app compares this calculation with the source Next Review Due date.

StatusMeaning and next step
OverdueA confirmed deadline has passed. Inspect which master or recurring criterion caused it.
Urgent / Due SoonRecurring review is due today/tomorrow, or in two through seven days.
Current / CompliantEvaluated timing is in window. Still review checklist evidence before your conclusion.
Missing DataRequired dates, signatures or evidence are absent.
Conflicting EvidenceSource dates or required evidence disagree.
Unable to EvaluateA date or level of care cannot be interpreted by the active rules.
Needs ReviewHuman resolution is needed, including LOC change or Day-1 mismatch.

LOC change: the displayed seven-calendar-day date is a provisional candidate. It is not an enforced compliance deadline. These cases remain Needs Review until R3/Marleigh confirms the duration, calendar/business basis and clock start. Do not approve a case solely because it meets that candidate date.

Settings displays clinical intervals read-only. Changing organization or timezone does not change them. Clinical policy changes need reviewed versioned rules, tests and release validation.

Upload and import

Manual Upload

Choose approved binder files. Enter an MRN correction only after verifying the source. Read every processing warning, then open the exact saved plan and inspect extracted fields. Text, PDF, DOCX and XLSX extraction is bounded; encrypted archive success alone does not prove all content was parsed. Image, legacy document and archive formats may be retained as opaque content without clinical extraction. Do not treat them as a completed checklist.

Alleva pulls

An authorized administrator can refresh patient roster independently from full treatment plans. Both require the appropriate approved connection. Wait for completion and inspect counts, warnings and failures. A successful connection test does not prove all pages or plan details were imported.

Office managers should ask the administrator to investigate connection or live-import problems. API Testing Harness, Settings and Forensic Logs are administrator functions; historical screenshots may show more access than your account. Live pulls remain gated until R3/Alleva approval and validated mapping.

Password and recovery

Use Account to change your password or generate a replacement recovery code. A code is displayed once and works once; store it as carefully as your password. Use Forgot password on the sign-in screen with your username, saved code and new password. Successful recovery uses the code and invalidates older sessions; sign in and save a replacement code.

If both password and code are lost, contact an authorized administrator/R3. A disabled account needs an administrator. There is no universal bypass password. Do not edit local configuration files or try an old reset executable on a newer release.

OneDrive ZIP backup and restore — configured source laptop

This laptop uses a separate portable ZIP workflow, not the encrypted .izcnabackup restore tool. ZIPs are not password protected: they include the database, local settings and encryption keys, uploads, logs and exports. Treat the entire ZIP as sensitive clinical data and credentials. Keep its OneDrive folder private under R3 access controls; do not email or share it publicly.

Create and check a backup

  1. Save your work and wait for uploads and API jobs to finish. Double-click (8) Back Up IZ Data to OneDrive. The app briefly stops and restarts if it was running. Do not use Start during backup.
  2. Wait for the verified-success message. The archive is named IZ-local-data-YYYYMMDD-HHMMSS-microsecondsZ.zip; its timestamp is UTC. Open your organization OneDrive folder, then IZ Clinical Notes Analyzer Backups.
  3. Confirm a new ZIP exists and OneDrive reports that synchronization is complete. A local ZIP or successful task alone does not prove cloud upload. Check the file through OneDrive on the web before relying on it for computer-loss protection.
  4. The task IZ Local Data ZIP Backup runs every three days at 6 PM while the configuring Windows user is signed in. Missed runs are attempted when available. A failed run leaves older ZIPs intact; retry manually when idle. Check %LOCALAPPDATA%\IZ Backup Status\last-result.json for the most recent success/failure. No older backups are automatically deleted.

The ZIP covers the active profile's settings, databases, uploads and other local files. Existing backup folders, diagnostics bundles and transient SQLite journals are excluded; databases are copied using consistent SQLite snapshots. App binaries, Python, project code and OneDrive itself are not inside this data backup. The script checks file hashes, SQLite integrity, the app schema and encrypted payloads in an isolated extraction before publishing the archive.

Restore on this laptop or a replacement computer

  1. Download a complete ZIP from OneDrive. Keep the original archive unchanged. Use R3 support to prepare the same app version/build first; newer versions require a separately validated upgrade. This source workflow requires the matching project, built frontend, and its working Python runtime.
  2. On a new Windows account, start the prepared app once, then stop it. On an existing account, save all work and let uploads and imports finish. Restore replaces the entire profile as of the backup date, including accounts and passwords; it does not merge records.
  3. Double-click (9) Restore IZ Data from ZIP, select the downloaded ZIP, and type RESTORE. If the shortcut is absent, support opens PowerShell in the matching project folder and runs powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\restore-onedrive-zip.ps1.
  4. The script stops the app, validates and stages the complete archive, and preserves the current data in %LOCALAPPDATA%\IZ Clinical Notes Analyzer-before-restore-TIMESTAMP before activating the restored profile. It refuses a corrupted archive. Do not extract individual files over live data or use the .izcnabackup Restore command for these ZIPs.
  5. Use Start and sign in with the password valid at the backup date. Confirm expected records, settings, latest dates, and opening an uploaded document. Recovery codes also reflect the backup date. Keep the preserved profile until R3 confirms restoration. If checks fail, stop the app and have support preserve the failed profile and rename the before-restore folder back to IZ Clinical Notes Analyzer; never merge the two folders.
  6. On a replacement computer, recreate desktop shortcuts and register the backup task for its Windows account. Desktop shortcuts and Task Scheduler registration are not restored by the data ZIP.

Synthetic restore tests verify portability without Windows-account encryption. A physical replacement-device rehearsal and OneDrive cloud-upload verification remain separate checks. If custom database or profile paths are configured, these scripts refuse backup and support must migrate that configuration first.
