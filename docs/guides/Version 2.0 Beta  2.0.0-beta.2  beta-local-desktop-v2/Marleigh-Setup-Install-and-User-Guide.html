Before you begin

This app runs only on the Windows laptop where it is installed. It opens in a web-browser window, but the app and its data remain on the laptop unless an authorized Alleva pull is run.

This is a beta release. Use it as an audit and review aid. If the app says Missing Data, Needs Review, Conflicting Evidence, or Unable to Evaluate, do not guess or treat the plan as compliant. Confirm the source record in Alleva and follow R3 policy.

Have these items ready

  • The prepared release zip named IZ-Clinical-Notes-Analyzer-v2.0.0-beta.2.zip.
  • The one-time admin password supplied through an R3-approved secure method. The app does not email this password.
  • For Alleva setup: the approved client ID and client secret from R3/Alleva. Do not place either value in a screenshot, email, or chat.
  • A Windows 10 or 11 laptop signed in under the Windows account that will use the app.
Stop and contact R3 support if the release zip or one-time admin password did not come from an authorized R3 source. Do not download a replacement from an unknown link.

Install the app

  1. Save the release zip locally. Put it in Downloads or another normal folder on the laptop.
  2. Unzip it. Right-click the zip, choose Extract All, and then choose Extract. Do not try to install while viewing files inside the zip.
  3. Open the unzipped folder. Double-click Install-IZ-Clinical-Notes-Analyzer.cmd.
  4. Wait for completion. A black setup window will show progress. Normal installation does not require administrator access. Do not close the window while setup is working.
  5. Look for success. The window should say Install completed. Then use the new IZ Clinical Notes Analyzer Desktop or Start Menu shortcut.
Installing a newer prepared release preserves the existing local app data and creates a verified pre-upgrade backup when data already exists. Do not use Complete Uninstall for an update.

Start and sign in

  1. Double-click the IZ Clinical Notes Analyzer Desktop shortcut, or open it from the Start Menu.
  2. Leave the startup window open. The browser should open automatically after the local app is ready.
  3. Sign in with username admin and your password.
  4. On the first sign-in, create a new password. Use a long, unique password and store it only in the R3-approved password system.
Five failed sign-in attempts temporarily lock the account for 15 minutes. Pause after one or two failures and verify the password instead of repeatedly guessing.

Set up the approved Alleva connection

Do this only when R3 has authorized the laptop and supplied the Alleva client ID and client secret. The app begins with live pull controls blocked on purpose.

  1. Open Settings.
  2. Confirm the organization and facility timezone. Do not mark the LOC-change window as validated until R3/Marleigh has confirmed the exact rule.
  3. In Alleva readiness profile, leave the standard Alleva URLs unchanged unless authorized support gives you different values.
  4. Paste the approved Client ID and Client secret. The secret becomes write-only after saving: the screen will show only that it is configured.
  5. Check Enable API testing and save. Use Test saved OAuth connectivity.
  6. Only after the approved read-only import gate is confirmed, check Enable treatment-plan sync and Authorize live read-only treatment-plan import for this tenant, then save again.
  7. Confirm the requirement list is cleared before starting a treatment-plan pull.
Never send the client ID, client secret, local app password, token, or a screenshot containing those values to support. If a secret may have been exposed, stop using it and report the exposure through the approved R3 security channel.

Daily treatment-plan audit

Daily sequence: Status Dashboard → Treatment Plans Roster → Pull full treatment plans → Patient Roster or Treatment Plan Detail → review evidence and checklist → document the manager action → sign out.

1. Check source readiness

Open Status Dashboard. Review the three source-readiness cards and the risk counts. Yellow warnings require attention but do not necessarily mean the app is broken.

2. Pull treatment plans from Alleva

  1. Open Treatment Plans Roster.
  2. If the pull button is disabled, read the requirement list and return to Settings. Do not bypass a blocker.
  3. Choose Pull full treatment plans. Leave the browser open while the job is working.
  4. When the pull finishes, choose Refresh roster if the new rows do not appear automatically.
  5. Search by MRN, patient name when authorized/displayed, or treatment-plan ID.

3. Review the patient and exact plan

  • Use Patient Roster to locate the MRN, then select the correct treatment plan.
  • Use Treatment Plan Detail to review the plan lineage, evidence coverage, dates, level of care, and 42-step checklist.
  • Read the source-evidence location before making a manager decision. The app's deterministic rules support the review; they do not replace clinical judgment or source verification.
  • Use Return, Approve, comments, or an override only when the record supports the action. Enter the required reason; never use a vague reason such as “fixed.”

Missing Data

A required date, LOC, signature, or source field is absent. Get the missing source evidence.

Needs Review

Evidence exists but requires a manager decision. Review the highlighted reason and source.

Conflicting Evidence

Two sources disagree. Do not choose one silently; reconcile the source records.

Unable to Evaluate

The app cannot make a safe determination. Handle it as unresolved, not compliant.

4. Use Help and forensic logs

Help repeats the basic workflow. Forensic Logs lets an administrator confirm that actions were recorded without patient names, clinical narrative, or vendor secrets.

Manual upload

Use Manual Upload when an approved treatment-plan file must be reviewed without an Alleva pull. Prefer text-extractable PDF, DOCX, XLSX, CSV/TSV, RTF, Markdown, or text sources.

  1. Open Manual Upload.
  2. Choose the approved treatment-plan file or binder files.
  3. If the file omits the MRN, enter the correct MRN. If it conflicts with detected evidence, check the correction confirmation only after verifying the patient.
  4. Choose Upload and securely process binder.
  5. Review every warning. Image-only or legacy formats may be stored securely without being parsed.

Manage users

Use Users to create counselor, office-manager, or viewer accounts and assign facilities/patients. Give each person a separate account. Do not share the admin password.

  1. Enter the new user's username and full name.
  2. Choose the least-privileged role that matches the person's job.
  3. Create a one-time temporary password and send it only through an R3-approved secure method.
  4. Assign the correct facility and patient access.
  5. Confirm the user changes appear in Forensic Logs without the password value.

Troubleshooting

What you seeWhat to do
The browser did not open.Wait one minute. Then open a browser and enter http://localhost:8000. If it still fails, use Stop IZ Clinical Notes Analyzer, then launch the app again.
The startup window shows a failure or stays on one message.Do not close it immediately. Take a screenshot that contains no credential or patient information. Run IZ Clinical Notes Analyzer Diagnostics and contact R3 support.
The page says it cannot connect.Use the Start Menu Stop IZ Clinical Notes Analyzer shortcut, wait for it to finish, then start the app again. Do not restart the whole laptop unless that fails.
Wrong password or locked account.After five failures, wait 15 minutes. If the admin password is still unavailable, contact authorized R3 support for local admin recovery. Do not edit hidden configuration files yourself.
Alleva pull button is disabled.Open Settings and follow the visible requirement list: saved client ID, saved client secret, API testing enabled, sync enabled, and tenant read-only authorization enabled.
OAuth test fails.Confirm the client ID/secret came from R3/Alleva, verify the laptop has internet access, and try once more. Do not paste the error together with credentials into email or chat.
Alleva is limiting requests.Wait several minutes before retrying. Repeated retries can extend the problem.
The pull finishes but the roster is empty.Choose Refresh roster. Confirm the pull completed rather than failed/cancelled. Check the Patient Roster. If still empty, capture the non-PHI status message and contact support.
A plan says Missing Data, Needs Review, Conflicting Evidence, or Unable to Evaluate.Open the plan detail, read the reason and source location, and reconcile the evidence in Alleva. Do not mark compliant just to clear the queue.
The display says no-name-found_....This is expected when patient-name import/display is off. Use the MRN and treatment-plan ID. Do not enable names unless R3 has approved it.
The LOC-change warning remains visible.Leave the setting unvalidated until R3/Marleigh confirms the exact update window. The current 7-day value is a configurable preset, not a confirmed rule.
You need to send support information.Send the app version, time of the problem, exact non-PHI message, and the redacted diagnostics package through the approved R3 support channel. Do not send the backup zip by ordinary email.

Security, backup, and closing the app

At the end of a work session

  1. Choose Sign out.
  2. Close the browser tab.
  3. If the app should be fully stopped, use the Start Menu Stop IZ Clinical Notes Analyzer shortcut.
  4. Lock Windows whenever stepping away from the laptop.

Back up before updates or major changes

Use the Desktop or Start Menu shortcut IZ Clinical Notes Analyzer Backup. The backup contains local clinical data and access material. Store it only in the R3-approved encrypted and access-controlled location.

Never share: the app password, Alleva client ID/secret, API token, local .env file, database, raw logs, patient screenshots, clinical files, or backup zip through ordinary email, chat, GitHub, or a support ticket.
Uninstall choices: normal Uninstall removes app files but preserves local data. Complete Uninstall removes the app and all local data for the Windows user. Use Complete Uninstall only when R3 intentionally wants the laptop cleared and after an approved backup.
