# Version 1.0.2 recurring treatment plan deadlines

Build 2026.10.16.1, stable-local-desktop. Validation: `../validation/current-work-2026-10-16.md`.

Recurring updates use the last updated date of the patient's most recent saved treatment plan, plus the configured LOC interval: PHP 30 calendar days; IOP/Outpatient 60 calendar days. Admission, original creation, local import time and signed review dates do not replace the plan update date. Timestamp offsets are interpreted in the facility timezone.

The Status Dashboard selects one most recent plan per authorized patient record by last updated timestamp, using current versions of source plans. Overdue means the computed next update deadline is before facility-local today. Due Soon includes today through the tenth following Monday-Friday business day, with no holiday exclusions. Weekend deadlines within that date range count. An older plan does not contribute an additional overdue count when a newer plan exists. Overall checklist review status does not mask a valid recurring deadline.

Missing or invalid update dates, unknown LOC and future update dates do not produce guessed deadlines. If source plans cannot be ordered because update dates are missing, or equally recent plans have conflicting computed deadlines, the dashboard excludes that patient record and explains the exclusion. Separate patient records remain separate authorization identities even if their MRNs match. Counts reflect saved data and require an authorized pull to include new Alleva changes.

Workload, Review and data quality, and Urgent dashboard metrics and their dashboard-only calculations are removed. Checklist evaluation and correction workflows remain available elsewhere. The detail screen shows Next update due and explains its calculation basis; historical versions retain their own source dates.

Comments remain attached to the exact saved version where they were entered. Updated versions display comments from earlier versions of that same patient/source/plan identity, retaining author, date and original version. Comments are not copied to unrelated plans or other sources. Historical approvals and overrides do not apply to changed content. Repeated unchanged imports do not duplicate the comment history.

Checklist and rule package revision 1.2.1 retains 42 criteria and existing criterion keys while updating the recurrence anchor wording and invalidating old evaluation reuse. Missing Data, Needs Review, Conflicting Evidence and Unable to Evaluate remain distinct. The separate LOC-change update window remains unvalidated and configurable; the seven-day preset is not clinical approval. Live Alleva approval gates are unchanged.

The existing administrator password, local user configuration and clinical database are not reset or replaced. Automated verification uses isolated synthetic data. This source maintenance release does not establish live-tenant or installer qualification.
