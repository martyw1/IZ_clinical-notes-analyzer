# Current V2 data contract

Source **1.0.1 / build 2026.10.12.1 / stable-local-desktop**. Backend contracts: `backend/app/v2/domain/schemas.py` and `backend/app/v2/api/models.py`; frontend: `frontend/src/v2/types/treatmentPlan.ts` and `identity.ts`.

`TreatmentPlanAggregate` retains MRN in compatibility field `patient_id`, source mode, display label and authorized full-name field, lifecycle/status/LOC/admission/history, plan/review/signature content, source update time, source/computed/LOC candidate dates, warnings, exactly 42 criterion results, manager reviews/overrides, audit references, evidence coverage, content snapshot, source-document references and checklist/rules/evaluation/timezone provenance. Missing names, references and dates remain unavailable; values are not invented.

MRN is not a globally unique authorization selector. Patients have a source/facility-scoped structural `patient_record_id`; selected saved plans have immutable `plan_version_id` and treatment-plan ID. Detail API response adds these exact identity fields. Frontend carries `patientRecordId` and `planVersionId` with source mode and plan ID; protected backend selectors validate accessible scope and reject ambiguous/mismatched identifiers. A new import cannot silently replace the saved version a reviewer selected.

`GET /api/v2/patient-roster` returns authorized patient rows and linked plan choices, including patients without a plan. `GET /api/v2/treatment-plan-roster` returns saved Manual and Alleva plan rows with identity, names when authorized/available, source timestamps and lineage. Exact detail routes include `/api/v2/patients/{patient_id}` and `/api/v2/treatment-plans/{patient_id}/{treatment_plan_id}` with required source/exact-identity query fields.

Full patient source objects are encrypted snapshots; authorized displays may derive names from them. Names never substitute for MRN/source relationships, and must not appear in forensic details or diagnostic exports. The plan content graph contains needs, problems/diagnoses, goals/objectives/interventions, typed signature metadata, observed fields and safe evidence paths. Signature images/base64 and raw clinical narrative must not enter ordinary logs. IDs/dates and authorized source views remain sensitive even when name-free exports are used.

Changed imports preserve immutable prior plan versions; identical replays avoid duplicate versions. Source-document memberships attach exact saved versions. Persisted evaluations retain rule/checklist/date/timezone provenance; corrections and manager decisions must preserve their exact plan context. Structural storage/migrations are documented in [patient handling](../patient-treatment-plan-handling.md).

All release fixtures/screenshots use isolated synthetic data. Current rules have read-only Settings intervals and an unvalidated LOC candidate. Live vendor use requires external approval. [Current validation](../validation/current-work-2026-10-12.md) supersedes historical beta reports for current acceptance.
