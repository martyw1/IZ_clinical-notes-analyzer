- Added local SQLite-backed V2 foundation models for users, app settings, encrypted API configuration state, and hash-chain audit events. Admins can now run a persisted hash-chain verification from Forensic Logs; the result reports the audited-event count and first invalid database record without returning audit-detail payloads.
- Added local SQLite-backed treatment-plan aggregate imports. The default protected V2 queue is empty until a real normalized aggregate is imported.
- Added `POST /api/v2/manual-uploads/treatment-plan-aggregate` for role-gated normalized V2 aggregate import. The full aggregate payload is encrypted at rest; queue metadata stores patient ID, status, LOC, dates, and non-secret counts only.
- Wired the Manual Upload page to import a JSON aggregate file through the backend and then render the imported patient in Treatment Plans queue/detail.
- Added `POST /api/v2/manual-uploads/treatment-plan-file` for role-gated UTF-8 text, Markdown, CSV, TSV, readable PDF, and XLSX treatment-plan uploads. The parser accepts labeled treatment-plan fields, supports a Patient ID override fallback, requires an explicit manager confirmation when a file ID conflicts with a supplied correction, builds a canonical 42-step V2 aggregate with nested problem/diagnosis/goal/objective/intervention/signature content, encrypts the persisted aggregate, archives the original source file encrypted under OS-local app data, and audits only redacted metadata.
- Wired the Manual Upload page to post supported files as `FormData` through the backend, report encrypted source-file archival, and then render the parsed patient in Treatment Plans queue/detail.
- Added Treatment Plan detail source-file archive controls. Archived manual source files now render as safe metadata, and manager/admin users can download the decrypted original bytes through an audited, role-gated, path-safe route with a generated filename rather than the original upload name.
- Added readable PDF and XLSX manual parsing. PDF text extraction uses bundled `pypdf`; XLSX extraction uses bounded standard-library OpenXML parsing for labeled cells, with archived source downloads preserving generated `.pdf` and `.xlsx` filenames.
- Added manager/admin source-file lifecycle delete controls. Deleting an archived source file removes only the encrypted original source bytes and source metadata, preserves the normalized treatment-plan aggregate, refreshes the Treatment Plan detail panel, and writes a redacted audit row.
- Added durable V2 manager-action persistence. Manager approve/comment/return/override payloads are stored in SQLite, merged back into Treatment Plan detail as `manager_reviews` and `overrides`, survive app restart, and continue to create audit rows.
- Added a Treatment Plan detail history panel showing persisted manager actions from backend detail data after reload/navigation.
- Added an append-only return-for-correction workflow. Manager/admin returns now create dynamic open-return counts, counselors receive a protected Corrections queue, counselor resolution notes create a durable `correction_submitted` action for manager review, and the queue closes only for that criterion's latest submitted/approved/overridden state. Counselor attempts to save a manager action are denied and recorded as a redacted audit event; manager-only review and source-file controls are hidden from counselor Treatment Plan views.
- Replaced static V2 dashboard/readiness claims with persisted local state. Dashboard cards now reflect whether normalized treatment-plan records exist, whether an encrypted API credential is saved, whether API testing is enabled, and how many returns remain open; readiness exposes the saved/enabled API profile state while preserving the unvalidated LOC-change warning.
- Replaced the static OpenAPI definition response with a protected server-side pull from the saved API profile. The bounded loader accepts only absolute HTTP(S) URLs, limits responses to 2 MiB, validates JSON `paths`, returns only a definition title and operation count, and writes a redacted audit summary; Settings can now invoke the pull directly.
- Added a protected saved-profile OAuth client-credentials test. Body and HTTP Basic styles use the encrypted client secret only in the server process, discard the obtained token immediately, return fixed safe metadata only, and record an audit outcome without token, secret, URL, or upstream response content. Settings now exposes the token URL, auth style, scopes, timeout, API-test enable flag, and credential test action.
- Added a protected read-only operation test in the API Testing Harness. It permits only `GET` with a normalized relative path against the saved base URL, requires API testing to be explicitly enabled, uses an in-memory OAuth token, caps captured bytes at 64 KiB, and returns only safe HTTP status/content-type/byte-count metadata.
- Replaced the synthetic all-fields job loop with a saved-profile OAuth-backed paged `GET /treatment-plans` runner. Job lifecycle state is persisted in SQLite, restarted active jobs are marked stale, cancellation is visible in the UI, artifacts retain only redacted external record metadata, and pagination/sync limits are configurable in Settings. The browser validation used a local mock OAuth/API server; live Alleva sync remains gated.
- Added a separate approved Alleva treatment-plan sync path. It uses the saved encrypted OAuth profile for real read-only `/clients`, paged `/treatment-plans`, and per-plan detail requests, maps client identifiers to plans, normalizes and encrypts the resulting V2 aggregate, and records redacted sync outcomes. The browser starts a persisted job and polls its terminal state rather than holding the request open; an admin can cancel a queued/running sync, and unexpected worker errors become redacted failed jobs instead of remaining running. It remains disabled until an admin saves all four gates: API testing enabled, sync enabled, R3/Alleva approval recorded, and endpoint mapping validated. Settings exposes each gate, run status, cancellation, and the run action.
- Corrected Alleva checklist provenance. The deterministic 42-step parsed-field evaluator now retains `Alleva REST` endpoint provenance for every synced criterion and observed field instead of presenting API-derived evidence as manual-upload evidence.
- Added a deterministic persisted date-clock decision. A trusted explicit next-review due date now produces `Late` or `Within Window`; unavailable admission, LOC, signature, or due-date evidence produces `Missing Data`; a malformed due date produces `Unable to Evaluate`. The app does not derive compliance from missing dates. When source data contains more than one LOC history entry, the still-unvalidated LOC-change rule forces `Needs Review` rather than a compliance decision.
- Enforced the local password-reset lifecycle. Admin-created/reset users are restricted to profile/password-change routes until they submit a compliant new password; the reset form withholds workspace navigation, and successful change clears the reset/lock state with a queryable audit event.
- Wired the admin Users page to the existing protected user APIs. Admins can create counselor/office-manager/viewer accounts with a temporary password and reset non-bootstrap accounts; the list reloads from SQLite and never displays the temporary or reset password.
- Added persisted workflow profiles with draft version creation, manager-readable version lists, admin-only publishing, duplicate-key protection, and redacted audit rows. The Workflow Profiles page loads profiles from the protected backend and publishes only draft versions through the authenticated API; real-Chrome E2E proves create, publish, persistence, and audit behavior against an isolated desktop SQLite runtime.
- Hardened V2 checklist evidence export and API harness artifact downloads. CSV export now uses the standard CSV writer plus spreadsheet-formula neutralization for text cells; API harness downloads are limited to known generated artifact filenames instead of raw path joins.
- Added frontend coverage proving invalid login is rejected, login fetches the protected app shell, non-admin roles do not see admin-only navigation, treatment-plan review actions call the backend, write-only API secrets are not echoed, and API harness jobs/artifacts use backend endpoints.
- Verified the desktop app visually at desktop and narrow mobile widths through normalized JSON upload, parsed text upload, Treatment Plans queue/detail, and manager-review surfaces using synthetic non-PHI evidence.

## Boundaries preserved

- Alleva live treatment-plan sync remains disabled by default and gated until R3/Alleva approval, tenant endpoint mapping, pagination/rate-limit behavior, attachment behavior, auth requirements, vendor documentation, and compliance approval are complete.
- The LOC-change treatment-plan update window remains configurable and marked unvalidated until R3/Marleigh confirms the rule.
- Synthetic fixture data remains isolated to fixture/helper modules; production V2 treatment-plan pages now load persisted imports through backend APIs.
- Current manual upload support accepts normalized V2 aggregate JSON plus UTF-8 text, Markdown, CSV, TSV, readable PDF, and XLSX files with labeled treatment-plan fields. Supported source files are archived encrypted at rest without storing original filenames and can be downloaded or deleted later by manager/admin users through audited source archive controls. A conflicting file Patient ID and override now requires explicit manager confirmation, with a redacted audit event and aggregate warning. Scanned/non-extractable PDFs and multi-document binders remain open implementation stations.
- No PHI, credentials, local runtime files, uploaded notes, databases, logs, tokens, or vendor secrets are documented here.
